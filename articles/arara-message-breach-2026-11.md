2026年10月末、メール配信サービス「アララメッセージ」への不正アクセスが公表されました。
第一報の共用環境・メールアドレス約301万件から、第2報では契約企業向け環境のサーバー97台からもデータ持ち出しが確認され、メールアドレスは約7,700万件（精査中）とされています。
この記事は、ペイクラウドホールディングス／アララの適時開示と利用企業の公表から事実を整理し、同じ構成のメール配信SaaSを使う組織が何を見直せるかを考えるものです。先に結論を書くと、件数が大きいことより、「配信基盤を経由して契約企業向け環境へ広がった」ことと、「正規の送信ドメインから不審メールが送られた」ことの2点が、手元の設計見直しに効く、というのが自分の見立てです。個人の利用者の方は、まず後半の「B. 最終ユーザー」チェックリストへ進んでください。

:::message
**TL;DR**
- アララ（親会社ペイクラウドHD）第2報（11/2）時点で、影響は大きく3区分。（1）本サービス経由で契約企業向け環境のサーバー97台（対象企業数は精査中・推計最大約380社）からメールアドレス等 約7,700万件、（2）共用環境 61社・メールアドレス 3,386,187件、（3）本サービスを不正利用した不審メール 最大約713万通。件数は区分間で重複し得るため合算していない（約7,700万件は人数ではない）。
- 原因は「Webサーバーの脆弱性およびシステム環境における問題」。具体的な脆弱性名・侵入開始時期は公表されていない。サービスは10/31に全面停止、再開時期は未定。
- 直前のユミルリンク「Cuenote」事案と同型の「メール配信SaaS経由の委託先漏えい」だが、本件は契約企業向け環境への波及と、正規ドメイン（`news@arara.com`）からの不審メール送信が公式に示されている点が異なる。経路の詳細（サーバー間の移動か、共通経路からの同時侵入か）は未公表で、本記事も断定しない。
:::

**2026年11月2日時点**（利用企業の個別公表は11/4時点まで参照）の公開情報にもとづく整理です。件数は精査中で、続報で変わる可能性があります。攻撃者の身元や脆弱性の詳細は推測しません。

## 登場する関係者

関係はざっくり「作っている会社 → 使っている企業 → その先の個人」です。

| 呼び方 | 誰か |
| --- | --- |
| アララ | メール配信サービス「アララメッセージ」を運営するアララ株式会社 |
| ペイクラウドHD | アララの親会社。東証グロースでの適時開示（第2報PDF）の主体 |
| ご契約企業 | アララメッセージを直接導入している企業（影響候補の推計は最大約380社。公式の確定値ではない） |
| 最終ユーザー | ご契約企業が配信するメールの宛先となる個人のお客様 |

ダスキンの公表では、会員サイト「DDuet」のメール配信に利用していた外部サービス名を「repica」（提供元アララ）と書いています。サービスブランド名の呼び分けは各社の表記に従い、本記事では親会社・子会社の適時開示に合わせて「アララメッセージ」と呼びます。

:::message
**「共用環境」と「契約企業向け環境」**
第2報は、みんなで使う箱（共用環境）と、契約企業向けに分かれたサーバー群（97台）を別区分で書いています。97台が物理か仮想か、1台に複数社が載っていたか（テナント分離の粒度）は**公表されていません**。「97台＝380社それぞれの自社サーバー」と読む根拠もありません。本記事では公式の「ご契約企業の環境のうちサーバー97台」という言い方を使い、インフラの所在は断定しません。
:::

**約7,700万件は最終ユーザー数ではありません。** 第2報は「個人の方が複数のアドレスを保持している可能性もある」と明記し、区分間の重複もあるため件数を合算していません。同じ人が複数回数えられている場合があり、実際の人数は件数より少ない可能性があります。「持ち出された恐れ」は「記録の読み取り量から判断したもの」とされています。報道や利用企業のお知らせで「約7,700万件／約380社」と要約されることがありますが、公式の区分表では（1）約7,700万件と（2）3,386,187件は別枠です。
:::

## 影響の3区分

### ① 本サービスを経由した不正アクセス（基盤経由）

- **発生**：10/28〜31、**把握**：10/31
- **対象**：ご契約企業の環境のうちサーバー97台（対象企業数は精査中、推計最大約380社。確定値ではない）
- **持ち出された情報**：メールアドレス、ご契約企業が登録した氏名・性別・生年月日・電話番号・会員番号・住所等（項目は企業により異なる）、配信の宛先等の記録
- **件数**：メールアドレス 約7,700万件（精査中）

第2報の文言は、「第三者の本サービスのサーバーへの不正アクセス」→「当該サーバーを経由して本サービスの多数のサーバーに侵入」→「データベースの内容を外部に持ち出し」です。サーバー間を順次移動したのか、共通の経路から複数サーバーへ到達したのか、テナント分離の方式は**公表されていません**。本記事ではこれを「契約企業向け環境への波及」と呼び、技術用語としてのラテラルムーブメント（横展開）とは言い切りません。

### ② 既報の環境（共用環境）の更新

- **発生**：10/27〜28、**把握**：10/28
- **対象**：ご契約企業61社
- **経緯**：管理画面への不正ログインと、データ出力機能等の悪用
- **更新後の件数**：メールアドレス 3,386,187件（重複を除く）。うちご契約企業5社が登録した氏名・会社名等を含む顧客データ 最大411,827件
- 第一報の「約301万件」から、調査で件数が更新されています

### ③ 本サービスの不正利用による不審メール（なりすまし送信）

| 項目 | 内容 |
| --- | --- |
| 送信期間 | 2026年10月28日〜30日 |
| 送信件数 | 最大約713万通（2つの環境の合計） |
| 送信元 | `news@arara.com`（第2報に明記） |
| 件名の例 | 「利用内容確認のご依頼」「ご利用明細確認のご依頼」等 |
| 送信先 | 第三者が外部から持ち込んだメールアドレス |
| 個人情報への影響 | この不正送信自体に伴う、メールアドレス以外の流出は確認されていない |

クレジットカード会社を装った不審メールだった、と第2報は書いています。送信先は漏えいしたリストではなく「外部から持ち込んだ」アドレス、という点も公式の区分です。

## 利用企業が公表している例

アララ側は「すべてのご契約企業に連絡し、対象かどうかは個別に連絡する」としています。公開されている利用企業側の例を2件だけ挙げます（網羅ではありません）。**これらの企業も委託先経由の影響を公表している側であり、各社の過失を示すものではありません。**

| 公表日 | 組織 | 件数・項目（各社の表現） | 出典 |
| --- | --- | --- | --- |
| 11/4 | IIJ（IIJmio） | メールアドレス 983,458件（解約済み含む）。属性情報の詳細はアララに確認中。カード情報は連携しておらず対象外 | IIJ／IIJmio お知らせ |
| 11/4 | ダスキン（DDuet） | メールアドレス 657,886件。氏名・住所・カード情報は含まれない。委託先サービス名は「repica」（提供元アララ） | ダスキン PDF |

IIJmioは、正規の案内メール（`support@iijmio.jp` 等）を本件を理由に受信拒否しないよう注意を呼びかけており、「家族割引」の適用条件との関係も説明しています。委託先事案では、**利用者が正規連絡まで止めない**ための案内も実務上必要になります。

## Cuenote事案との違い（事実の範囲で）

自分は先にユミルリンク「Cuenote」の整理記事を書いています。どちらもメール配信SaaSの侵害ですが、公表されている構図は次のように違います。

| 観点 | Cuenote（ユミルリンク第2報時点） | アララメッセージ（第2報時点） |
| --- | --- | --- |
| 件数の言い方 | 延べ約5,162万件（漏えいの恐れ） | 約7,700万件等（区分別。合算なし） |
| 広がりの描かれ方 | ライブラリ脆弱性、サポート／QA認証情報、不正プログラム、複数システムへの波及 | Webサーバー脆弱性＋システム環境の問題、本サービス経由で契約企業向け環境のサーバー97台 |
| 配信基盤の悪用 | 迷惑メールの確認は同社ドメイン等で言及あり | 正規送信元 `news@arara.com` から最大約713万通の不審メールを公式に区分 |
| サービス継続 | 予防停止・再開の経緯が時系列で詳しい | 10/31に本サービス全面停止、再開未定 |

どちらが「より深刻か」といった比較はしません。読む側が同じ対策メモをコピペしないための地図です。

## 公表されている対応

アララ／ペイクラウドHDが第2報で示している対応の要点です。

- 不正に使用された認証情報の無効化、各サーバーの通信遮断
- アララメッセージの提供をすべて停止（10/31 19:53完了）。再開は侵入経路の特定、認証情報の全面変更、安全性確認の後。再開時は契約企業に管理画面パスワードやAPIキー等の再設定を依頼予定
- 外部専門機関と連携した調査、監視強化、システム再構築
- 最終ユーザー向けに、なりすまし連絡への注意と、`news@arara.com` の該当メール削除を案内

利用企業側（IIJ・ダスキンの例）では、影響範囲の確認、フィッシング注意喚起、委託先管理体制の再確認が書かれています。

## 明日から手元で使えるチェックリスト

本件の原因を特定したものではありません。メール配信や同等の顧客連絡SaaSを使う組織と、最終ユーザー向けの一般的な確認項目です。

### A. 利用企業（情報システム・個人情報管理）

**最優先:** 委託先に渡している項目の最小化、管理画面アカウントの棚卸し（多要素認証の有無を含む）。

- [ ] メール配信・SMS・プッシュ等の**委託先台帳**に、製品名（例: アララメッセージ／repica）と契約形態（共用／専用）が書かれているか
- [ ] 委託先に渡している項目は、配信に必要な最小限か（氏名・住所・電話・会員番号まで渡していないか）
- [ ] 委託先管理画面のアカウントに **MFA（多要素認証＝パスワード以外の確認）** があるか、退職者・代理店のIDが残っていないか
- [ ] APIキー・Webhook・SFTP連携の**ローテーション手順**と、侵害時の無効化窓口が分かっているか
- [ ] 委託先が「サービス停止」したときの**代替配信手段**（重要なお知らせの置き場）があるか
- [ ] 顧客向け案内で、「正規の送信元アドレス一覧」と「本件を理由に正規メールを拒否しないでほしい」をセットで出せるか（IIJmioの案内が参考になる）
- [ ] 委託先から「対象／非対象」の連絡が来る前提で、問い合わせ窓口とFAQの下書きがあるか

### B. 最終ユーザー

**最優先:** `news@arara.com` の該当メールは開かず削除。公式サイト以外の案内リンクは踏まない。

- [ ] `news@arara.com` から 10/28〜30 に「利用内容確認」「ご利用明細確認」等のメールが来ていないか。来ていれば **URLは開かず削除**。カード情報を入れてしまった場合はカード会社へ連絡
- [ ] 利用中のサービス（通信・小売・会員サイト等）から「委託先の不正アクセス」案内が来ていないか。公式サイトのドメインから確認する
- [ ] 不審なSMS・電話・郵便でパスワードやカード番号を聞かれたら応じない（アララ／ペイクラウドHDも「こちらから入力を依頼するメールは送らない」と明記）

### C. 同種SaaSを提供する側（一般論）

**最優先:** 契約企業ごとの権限・データの分離図を更新できるか。正規ドメインからの異常大量送信を止められるか。

- [ ] テナント（契約企業）間で、管理画面・API・データ出力の権限とネットワークがどこまで分離されているかを図にできるか
- [ ] 「1つの侵入が多数サーバーへ」つながる経路（共通認証、共通の管理面、共有の運用鍵）の棚卸しがあるか
- [ ] 正規ドメインからの大量送信を、契約企業の正規配信と区別して止められるか（送信レートの上限、承認フロー、異常検知）
- [ ] 第一報の範囲が後から広がる前提で、契約企業への連絡テンプレと件数の定義（延べ／重複除く／読み取り量）を先に決めてあるか

## おわりに

メール配信SaaSは、多くの組織にとって「自社の会員DBそのもの」ではなく「送り先リストを預ける場所」です。それでも第2報が示すのは、預ける項目の設計と、委託先の停止・なりすましまで含めた連絡設計が、件数の前に効くということです。

続報で件数や原因の書き方が変わったら、この整理も更新します。誤認や抜けの指摘は歓迎です。
